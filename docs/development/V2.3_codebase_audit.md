# V2.3.0 — Codebase Audit

Stage 1 of the V2.3.0 work order. Scope: read the current code and decide, per
component, whether the strategy-backtesting subsystem can **reuse** it, must
**extend** it, or must be **isolated** from it. No engine code was written for
this document.

- Baseline: `docs/development/v2.2.3_baseline/` (296 tests pass, `compileall`
  clean, CLI run on 000369 exit 0, database backup taken *before* the audit).
- Method: static reading of `fa/`, targeted greps, plus the read-only data audit
  in `scripts/audit_backtest_data.py` (Stage 2, separate document).
- Constraint carried over from V2.2.3: **no change to V2.2 public interfaces or
  output** in this batch.

## 1. Current layering

```
fund_analyzer.py / fund_analyzer_gui.py     thin shims
fa/cli.py                                   argparse entry point (flat flags)
fa/pipeline.py                              analyze_fund() — the V1 pipeline
fa/gui/*                                    Tk windows (main, post-market, QDII)
fa/analysis/nav_estimator.py                orchestrator for one QDII estimate
fa/analysis/returns/*                       four asset calculators + FX helper
fa/analysis/valuation/portfolio_valuation.py  weights → coverage → Shapley
fa/analysis/estimation_backtest.py          CSV-based validation of past estimates
fa/analysis/{technical,risk,post_market,portfolio_return}.py  V1 analytics
fa/analysis/{price_alignment,valuation_dates}.py  date logic
fa/models/*                                 Asset, HoldingSnapshot, PriceSeries, FxSeries, results
fa/data/*                                   downloads (NAV, holdings, quotes, FX) + storage
fa/data/database/*                          SQLite schema, connection, Repository
fa/utils/{calendars,data_quality,cache,net,logging_setup}.py
```

Data flows in one direction: `data` → `models` → `analysis` → `database` /
`serialization` → `gui`. The current violations of that rule are listed in §3.

## 2. Component verdicts

| Component | Current state | Verdict | Why |
|---|---|---|---|
| `fa/models/asset.py` | `AssetType` (4 + unknown), validation, currency normalisation | **Reuse as-is** | The strategy backtest values the same instruments with the same validation. |
| `fa/models/market_data.py` | `PricePoint` / `PriceSeries` / `FxSeries`, finite-positive validation, available/used price type | **Extend** | Works for valuation; a backtest additionally needs an availability time (`price_timestamp` is never populated today, see F-03) and an execution-price notion. |
| `fa/models/holding.py` | `HoldingSnapshot` with weights, disclosure metadata, `snapshot_from_rows` | **Reuse as-is** | A strategy backtest consumes the same snapshot shape; PIT selection already exists. |
| `fa/models/return_result.py` | `ReturnStatus` (with `is_ok` vs `is_usable`), `AssetReturnResult`, `PortfolioReturnResult`, Shapley helper | **Isolate** | These are *valuation* results. A backtest produces trades, positions, equity curves and its own metrics; sharing the result model would force one schema to serve two meanings. |
| `fa/models/estimation.py` | `EstimationRun`, `EstimationResult`, `LookAheadStatus` | **Reuse (estimation only)** | Belongs to subsystem 1; the strategy backtest must not write these tables. |
| `fa/analysis/returns/*` | Four independent calculators returning `AssetReturnResult` | **Extend** | The calculators answer "what did this asset return between two dates". A backtest needs the same question answered per rebalance period — reuse, but do not add trade logic here. |
| `fa/analysis/valuation/portfolio_valuation.py` | weighted sum, coverage, uncovered, status, Shapley | **Extend** | Same maths for "value the portfolio on date X"; a backtest also needs position quantities and cash, which this function does not model. |
| `fa/analysis/price_alignment.py` | last-observation-on-or-before + four-band staleness | **Reuse as-is** | Exactly the alignment rule a backtest needs; do not re-implement. |
| `fa/analysis/valuation_dates.py` | Beijing tz, 15:00 cutoff, CN trading calendar | **Reuse as-is** | Trade-date ordering is shared. |
| `fa/utils/calendars/*` | CN/US/HK/JP plus name→code normalisation, `FallbackCalendar` flag | **Extend** | Correct base, but the exchange normalisation table is incomplete (F-05) and the backtest will expose it more often. |
| `fa/utils/data_quality.py` | score/grade, stale & excluded weights, assumption penalty, calendar fallback | **Extend** | The backtest must report the same quality dimensions per rebalance, not only per estimate. |
| `fa/data/{nav,qdii_holdings,qdii_market,fx}.py` | downloaders, date-range support added in V2.2.1 | **Reuse (read-only)** | The backtest may only *read* through the data layer; it must not gain its own fetchers. |
| `fa/data/database/{schema,connection,repository}.py` | 11 tables, versioned migrations, `save_/load_` for snapshots, prices, FX, NAV, estimations, backtest metrics | **Extend** | Reusable, but needs (a) an execution-price/availability column story, (b) a separate table for strategy-backtest runs, and (c) FX actually being persisted (F-06). |
| `fa/analysis/estimation_backtest.py` | CSV history, `backfill_history`, `compute_metrics`, `run_backtest` | **Extend (subsystem 1)** | Keep the file and the `backtest_results` table for estimate validation; add SQLite reads, grouping by model version / coverage bucket / look-ahead status. |
| `fa/analysis/portfolio_return.py` | V1 `holding_return` + `aggregate` (pandas, calendar-day staleness) | **Isolate (deprecate)** | Superseded by `returns/` + `valuation/`; still used by `post_market.py` and one test. Must not be reused by V2.3 (it has the deprecated interaction-term attribution). |
| `fa/analysis/nav_estimator.py` | orchestrator + legacy JSON serializer + private data helpers | **Isolate** | V2.3 must not extend it; the private helpers (`_market_data`, `_db_prices`, `_save_prices`) should move down to `fa/data/` first. |
| `fa/cli.py` | flat flags, no subcommands | **Extend** | A `backtest` subcommand requires a subparser; the existing flags must keep working. |
| `fa/pipeline.py`, `fa/gui/*`, `fa/viz/*` | V1 analysis pipeline and Tk UI | **Isolate** | Unrelated to backtest execution; V2.4 handles UI. |

## 3. Findings

| # | Severity | Finding | Evidence |
|---|---|---|---|
| F-01 | P1 | `estimation_runs` stores only the boolean `look_ahead_safe`; the four-state `LookAheadStatus` added in V2.2.1 exists in Python but never reaches SQLite, so a query cannot separate "estimated-disclosure" runs from "verified-safe" runs. | `fa/data/database/schema.py` (`estimation_runs`); audit report `estimations.schema_gap`. |
| F-02 | P1 | `estimation_backtest.py` reads and writes CSV only, never SQLite, and derives metrics without grouping; it also lazily imports `HISTORY_SUFFIX` / `load_nav_frame` from `nav_estimator`, which is an analysis→analysis cycle. | `fa/analysis/estimation_backtest.py:124-157`. |
| F-03 | P1 | `price_timestamp` exists in the model and the schema but is assigned nowhere outside the model/DB layer; there is no `available_at` concept. Every stored price therefore has no publication time, so a strictly point-in-time backtest cannot prove it used only information available at the decision moment. | grep `price_timestamp` → only `models/market_data.py`, `schema.py`, `repository.py`; audit `price_timestamp_coverage = 0.0`. |
| F-04 | P2 | `market_prices` primary key is `(ticker, price_date, price_type)`, so a second download overwrites the first row; two vendors can never coexist for one observation, and a re-download silently rewrites history instead of appending a revision. | `schema.py` `market_prices` definition; `Repository.save_prices` uses `INSERT OR REPLACE`. |
| F-05 | P1 | Exchange normalisation maps `NasdaqGS/NMS/NYQ/LSE/...` but not `EBS`, which is what Yahoo returns for Swiss (`ROP SW`, `NOVN`). Those tickers fall back to a weekend-only calendar and are flagged `calendar_fallback` in every run — cheap to fix, but it must be fixed *before* backtest date alignment relies on it. | audit `per_ticker` (`ROP SW`, `NOVN`: market `EBS`, `calendar_fallback: true`). |
| F-06 | P1 | `Repository.save_fx()` and `save_prices()` exist but the estimator never persists FX: `fx_rates` holds **0 rows** while five currencies were consumed. Price persistence only happens for the ~2-week lookback window. | audit `fx_rates.rows = 0`, `cross_checks.foreign_currencies_without_fx_series = [CHF, GBP, USD]`. |
| F-07 | P2 | `fa/cli.py` is a flat argparse; adding `backtest run` / `backtest report` requires converting to subparsers without breaking `python fund_analyzer.py 000369 ...`. | `fa/cli.py:60-96`. |
| F-08 | P2 | Two return engines coexist: `analysis/portfolio_return.py` (V1, interaction-term attribution) and `analysis/returns/` (V2, Shapley). V1 is still imported by `post_market.py` and `tests/test_analysis.py`. | `grep holding_return` → `post_market.py`, `tests/test_analysis.py`. |
| F-09 | P2 | The legacy JSON serializer lives inside `nav_estimator.py` (`_legacy_record`, `_legacy_row`), i.e. presentation code inside the orchestrator — a known, user-accepted deviation from `05_module_interfaces.md`. | `fa/analysis/nav_estimator.py:533-619`. |
| F-10 | P2 | `backtest_results` is named generically but is keyed by `run_id` → `estimation_runs`; it cannot hold strategy-backtest output without semantic overloading. A separate `strategy_backtest_runs` table family is required. | `schema.py`; `Repository.load_backtest_results`. |

## 4. Proposed isolation boundary for the strategy backtest

New package `fa/backtesting/` that **reads** through the existing data layer and
**writes** only its own tables:

```
fa/backtesting/
    models.py        StrategySpec, RebalanceRule, Position, Trade, EquityPoint, BacktestMetrics
    data_access.py   thin read-only wrappers over Repository (prices, FX, snapshots)
    engine.py        loop: rebalance dates → weights → quantities → trades → equity
    costs.py         commission / slippage / FX conversion assumptions
    metrics.py       CAGR, vol, Sharpe, MaxDD, turnover, hit rate (independent of risk.py)
    runner.py        run_id allocation, persistence, report generation
```

Rules:

1. `fa/backtesting/*` may import `fa.models.{asset,market_data,holding}`,
   `fa.utils.{calendars,data_quality}`, `fa.analysis.price_alignment` and
   `fa.data.database.repository`; it must **not** import `fa.analysis.returns`
   result types into its own result model, nor `fa.analysis.nav_estimator`.
2. Result models are separate. `backtest_results` keeps serving subsystem 1
   (estimation validation). Subsystem 2 gets `strategy_backtest_runs` /
   `strategy_backtest_metrics` / `strategy_backtest_trades`.
3. The engine owns no HTTP. Every price and FX series arrives via a
   `PriceSeries` / `FxSeries` obtained from `data_access`.
4. The engine never renormalises weights and never treats missing data as a 0 %
   return — inherited from the V2.2 principles.
