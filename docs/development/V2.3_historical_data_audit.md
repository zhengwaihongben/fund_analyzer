## 2. Dimension-by-dimension verdict

| Dimension | What a backtest needs | What exists | Verdict |
|---|---|---|---|
| Price history depth | Years of daily closes per market | **10 calendar days** (9–10 sessions) | **Insufficient.** No historical backtest can run on this; only fixture-driven engine tests. |
| Price cleanliness | No duplicates, positive values | 0 duplicates, 0 non-positive values, 100 % `adjusted_close` | **Sufficient** for the window that exists. |
| Price availability time | When each observation became known | `price_timestamp` is NULL for **all 93 rows** (coverage 0.0) | **Missing.** Point-in-time discipline cannot be proven from the database. |
| Price provenance | Vendor + revision history | single source `yahoo`, PK overwrites on re-download (F-04) | **Weak.** A vendor revision silently replaces history. |
| FX history | Daily CNY rates for USD/CHF/GBP/… | **0 rows**; `save_fx()` exists but is never called by the estimator | **Missing.** Any multi-currency backtest is impossible today. |
| FX coverage check | every foreign currency has a series | USD, CHF, GBP all absent | **Blocked** until F-06 is fixed. |
| Holdings history | One snapshot per quarter, with disclosure dates | **1 snapshot** (2026Q3) | **Insufficient for historical PIT.** By the V2.1 decision, quarterly history is no longer auto-downloaded; it must be imported explicitly. |
| Disclosure dates | Real filing dates | 2026-10-21 is *estimated* (quarter end + 21 days), flagged `disclosure_date_estimated = true` | **Usable but must be labelled.** Any PIT claim is "estimated-disclosure", not "verified-safe". |
| NAV history (subsystem 1) | Long daily series to score past estimates | 451 sessions (2025-01-02 → 2026-11-13) | **Sufficient.** This is the one dimension that is genuinely ready. |
| Estimation history (subsystem 1) | Many runs across many target dates | 17 runs, but only **2 distinct target dates** (2026-11-13 and 2026-11-16) | **Insufficient for MAE/RMSE.** Validation needs dozens of dates; today the metrics are `pending`. |
| Trading calendar correctness | Real holiday tables per market | CN/US/HK/JP real; GB/CH (incl. `EBS`) fall back to weekends | **Partial.** Fine for a 2-week window, not for years. |

## 3. What V2.3 can and cannot claim today

**Can be built and tested now**

- The strategy-backtest engine itself, against synthetic `PriceSeries` /
  `FxSeries` fixtures (the V2.2 test style already does this: no network).
- Cost/turnover/metrics maths, with unit tests.
- Report rendering over synthetic runs.

**Cannot be claimed now**

- "Backtest this strategy over 2023–2025." The database holds ten days of
  prices and no FX; the fetchers can request date ranges, but nothing has been
  persisted for any historical window.
- "Point-in-time safe." Availability time is absent and disclosure dates are
  estimated; the honest label is `estimated-disclosure`.
- "Multi-quarter portfolio backtest." One quarter of holdings exists.
- "Validate the estimator's accuracy." Two target dates are not a sample.

## 4. Required data work (feeding V2.3.1 / V2.3.2)

1. **Extend price persistence to the backtest window.** `_market_data()` already
   fetches by date range (`start`, `end`); the backtest data-access layer must
   request the full window and persist it (`save_prices` already exists).
2. **Persist FX** (`save_fx`) for every currency used by a run; without it the
   CNY conversion cannot be reproduced historically.
3. **Record availability.** Add `available_at` to `PricePoint` and populate it
   from the vendor response (Yahoo gives no publication time for end-of-day
   bars, so the convention must be explicit: "available at the market close of
   `price_date` + configured lag"). Store it in `market_prices`.
4. **Import quarterly holdings explicitly.** A small importer
   (`fa/data/holdings_import.py`, CSV → `HoldingSnapshot`) so historical
   quarters can be added by hand from filings; this is the accepted consequence
   of dropping automatic history download in V2.1.
5. **Freeze a golden backtest fixture.** One synthetic 2-year multi-currency
   dataset committed under `tests/fixtures/`, so the engine has a stable
   reference independent of the network.

## 5. Limitations recorded by the audit script

- `price_timestamp` present in schema, never populated (F-03).
- `(ticker, price_date, price_type)` primary key prevents two sources coexisting
  and silently overwrites on re-download (F-04).
- Calendars only real for CN/US/HK/JP; CH/GB/DE/FR/NL/CA/AU fall back to
  weekends and are flagged per ticker (F-05 adds `EBS`).
- FX series are CNY-based by convention; direction is not verified beyond
  positivity.
- Corporate actions are not modelled: `adj_close` supports return analysis but
  cannot reproduce historical share quantities or cash flows.

## 6. Conclusion

The **estimation-validation** subsystem (1) has enough NAV history to score
estimates, but not enough estimation history to produce meaningful metrics yet.
The **strategy-backtest** subsystem (2) has *no usable historical market data*:
it can be engineered and unit-tested now, but it cannot be run against real
history until the four data items in §4 are done. This is a data-acquisition
gap, not an architecture gap — the repository, models and date alignment already
support what is needed.
