## 4. B2.6-03 — stored mode stays read-only

Covered by `StoredEstimateTests` and `StoredModeReadOnlyTests` (B-2.4-01…08):
the estimator is never called, no Repository write method is invoked, JSON files
are neither created nor rewritten, an unknown run raises `LookupError`, the
Repository is closed on both the success and failure paths, and a run that only
has a summary still displays. The documented boundary still holds: the
connection opens through `connect()` (WAL + `initialise()`), so this batch does
not claim a `query_only` handle; it only proves no logical write happens.

## 6. B2.6-05 — asset source priority

Covered by `AssetSourcePriorityTests`, `SourcePriorityMergeTests` and the JSON
tolerance tests: SQLite inputs → per-run snapshot → latest JSON only when the
`run_id` matches; a higher-priority value is never overwritten; contribution and
status merge independently; an unmatched ticker or a foreign `run_id` supplies
nothing; a source label appears only when that source actually supplied data;
with no usable detail the message stays 「此執行未保存可用資產明細（僅存摘要）」；
`None` and `0.0` remain distinguishable.

## 7. B2.6-06 — numeric boundaries

Covered by `NumericNormalisationTests`, `LegacyHistoryTests` and
`AbnormalValuePresentationTests`: `None` stays `None`; `0` stays `0.0`; normal
numbers and numeric strings convert; invalid text never becomes `0`; NaN/±inf
and oversized integers (`10**1000`) become `None` without aborting the read;
nothing re-computes contribution, fills unknown weight/contribution with `0`,
clamps or re-sorts/dedupes the rows.
