## 2. Defect found before the fix

Twenty tests (B2.2-01 … B2.2-20) were written against the shipped code first;
five failed:

| Test | Symptom |
| --- | --- |
| B2.2-10 snapshot `holdings` is a dict | a blank asset row was synthesised from the dict's keys |
| B2.2-11 snapshot `holdings` has `None`/`"bad"` elements | `3 != 1` — invalid elements became blank rows |
| B2.2-12 snapshot `holdings` all invalid | blank rows plus the `執行快照 JSON` label |
| B2.2-19 latest `holdings` is a string | iterated character by character into blank rows |
| B2.2-20 latest `holdings` has invalid elements | `3 != 1` |

Root cause: `_resolve_asset_rows()` iterated `snapshot.get("holdings") or []`
and `latest.get("holdings") or []` directly, so any iterable (a string, a
dict) or any non-dict element reached `_from_holding()`, which returns an
all-`None` row. A non-empty list of such rows also made the caller claim the
JSON source.

## 3. Fix

`fa/application/estimation.py`:

1. New `_valid_holdings(payload) -> list[dict]`: returns `[]` unless `payload`
   is a dict whose `holdings` is a `list`; returns only the `dict` elements.
   Snapshot, latest JSON and the record fallback all use it, so the three
   paths share one validation rule.
2. `_read_json()` was left as is — its `except (OSError, ValueError)` already
   covers missing, empty and malformed files; no test produced another
   exception type.
3. `_snapshot_record()` was left as is — it already rejects a non-dict root,
   a non-dict `snapshots`, and a non-dict snapshot entry.

## 4. Stored-mode semantics under every failure

| Field | Value |
| --- | --- |
| `record` | the SQLite summary, unchanged |
| `mode` | `stored` |
| `persisted` | `True` |
| `run_id` | the requested run id |
| `asset_rows` | `[]` when no valid asset detail exists |
| `asset_source` | `""` when no valid source supplied rows |
| `message` | `此執行未保存可用資產明細（僅存摘要）` |

No JSON failure makes the run look missing, no value is replaced by 0, no
other `run_id` is read, no new estimate is started, and no file is written
back or repaired.
